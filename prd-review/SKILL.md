# PRD 技术审查

## 做什么

接收**已完成的 PRD**，执行审查闭环的前两阶段：

```
阶段 1 技术审查 → 结构化问题报告
阶段 2 交互问答 → 点选 UI 收集 PM 决策（完整模式：默认立刻弹出）
     ↓ 交接
阶段 3 重生成   → 由配套 skill prd-regeneration 完成（本 skill 不执行）
```

**核心分工：PM 做决策，AI 画图。** 图不要求 PM 提供；缺图不定级、不扣分——PRD 用文字/表格/规则表覆盖各图关注点即等价。AI 从文字/表格核对各图关注点（见各 framework 文首「本图关注点」），不确定处变成阶段 2 选择题，确认后交接给 prd-regeneration 生成验证图。

## 运行模式

| 模式 | 何时 | 行为 |
|------|------|------|
| **完整**（默认） | 未声明只要报告；或用户要澄清/重生成 | 阶段 1 → **同一轮**进阶段 2 → 收齐后输出交接物，声明「调用 prd-regeneration 重生成」 |
| **轻量** | 用户说「只审不改 / 只要报告 / 不提问 / 先别问我」等 | **仅阶段 1**；报告写清「完整模式可继续点选澄清」；**禁止**自动弹问答 |

轻量模式下不要问「是否进入问答」——停在报告即可。用户之后说「继续 / 提问 / 重生成」再进阶段 2 或交 prd-regeneration。

## 输入

| 输入 | 必需？ | 说明 |
|------|--------|------|
| PRD（HTML/MD/粘贴/链接） | **必需** | 没有则向用户索取 |
| UI 原型 / 设计稿、UX/DFD/状态机/流程/时序/ER | 可选 | **有则严格审；缺图不扣分——文字/表格覆盖该图关注点即等价** |

## 维度执行语义（强制，禁止简化错）

| 维度 | 有产物 | 无产物 |
|------|--------|--------|
| **D1–D10** | 始终审 PRD 文字 | 始终审 |
| **D11** | 按形态分级审（见 `references/ui-prototype-framework.md`） | **跳过、不定级** |
| **D12–D17** | 有图：按对应 framework **严格**审图 + 与 PRD 一致性 | **不因缺图定级/扣分**——按该维「关注点」核对 PRD 文字/表格/规则表覆盖（见对应 framework 文首「本图关注点」），覆盖即按关注点覆盖度打分；不确定 → 本维记问题进阶段 2；确定部分作为交接素材 |

详细问题与反模式：`references/review-checklist.md`。各图标准：对应 `references/*-framework.md`。

**归维去重：** 一题只挂一个主维度。规则/异常/歧义 → 优先 D6/D7/D9；仅当不确定点**直接决定验证图结构**时挂 D12–D17。禁止同一事实开两道题。

**同型缺口合并：** 多个模块缺同一类规格（如都无异常表）→ 审查可列多条，阶段 2 **合并为一题**（选项覆盖统一策略）；P0 模块优先单独问。详见 `references/qa-generation-guide.md`。

## 加载预算（强制，控制上下文）

不要一次性读完所有 references。按阶段与产物条件加载：

| 阶段 | 必读 | 条件读 |
|------|------|--------|
| 1 | `references/review-checklist.md`（D1–D10 + 文末评分指南）；`references/functional-module-framework.md`（D2 对照） | 有原型/设计稿 → `references/ui-prototype-framework.md`；**有某类图** → 对应 `references/*-framework.md`；**无图**时 D12–D17 只读 checklist 中该维「关注点」段 + 对应 framework 文首「本图关注点」，**不**预读全部图 framework |
| 2 | `references/qa-generation-guide.md` | — |
| 任意 | — | `references/eval-notes.md` / `references/fixtures/` 仅改 skill 或回归时读 |

PRD 与用户附件优先于 references；references 冲突时以 SKILL.md 本文件为准。

## 阶段 1：技术审查

1. 完整阅读 PRD；若有产物则完整阅读。
2. **模型推导（无论是否有图）：** 有状态实体 / 核心流程 / 前后端交互 / 多实体关系 / 核心用户任务 → 推导隐含模型；无图时按对应 framework 文首「本图关注点」核对文字/表格/规则表覆盖（覆盖不扣分，缺口/歧义记问题）。能唯一确定的记为交接素材；多种合理解读 → 审查问题（归维见上）。
3. 按 D1–D10 始终审；D11 / D12–D17 按上表。
4. 每个问题：定级（阻断/重要/建议）+ 引用原文 + 技术风险 + 具体改法。
5. 输出报告（有 `html-report` skill 则用；否则 HTML 文件或 Markdown），**结构固定**（报告是交接物，字段必须完整）：

```
# PRD 技术审查报告
## 一、结论（🔴 阻断 / ⚠️ 需修改 / ✅ 可开发 + 一句话理由；以 D1–D10 为准）
## 二、问题表（编号 | 维度 | 级别 | 原文引用 | 技术风险 | 具体改法）
## 三、详述（阻断/重要问题逐条展开，附原文与改法示例）
## 四、维度分（D1–D17；未执行维度标注「跳过（无原型）/ 无图，按关注点覆盖度」）
## 五、未澄清项（超题量或未确认的行业默认，禁止静默丢弃）
## 六、交接声明（完整模式：「下一步：调用 prd-regeneration 重生成」；轻量模式：「仅报告，未启动问答」）
```

6. **完整模式：** 报告交付后同一轮进入阶段 2，不要等用户说「继续」。**轻量模式：** 到此结束。

**严重程度（定级原则）：**

| 级别 | 含义 | 典型 |
|------|------|------|
| **阻断** | 实现路径不可判定或会做错且难返工 | 规则无后果且涉资损/安全；范围边界对某功能不可判定；模块被引用但无任何可实施规格 |
| **重要** | 不澄清会返工或验收扯皮 | 缺实体字段、异常表、歧义排序；**纯文档结构缺失**（无独立 OOS/验收章节但正文可推导） |
| **建议** | 可改进、可不进问卷 | 文案语气、命名偏好、说明偏长 |

**禁止**把「章节标题不标准」单独打成阻断——优先看开发能否唯一实施。细则见 checklist。
**缺图不参与定级。** 总结论一票否决以 **D1–D10** 为主。
**模块完整性定级两级制：** ⑦ 数据实体 / ⑧ 业务规则 / ⑪ 异常处理——正文完全无规格且不可推导 → 阻断；正文可推导但未成表/未成章节 → 重要。见 `references/functional-module-framework.md`。

**模块抽样（大 PRD）：** 模块 ≤5 则全审；更多时 P0/本次 In-Scope 全审，其余抽样 + 同型合并记问题。

## 阶段 2：交互问答（完整模式；强制点选）

**必读：** `references/qa-generation-guide.md`

### 工具探测（立刻 call，先于长文）

1. 有 `request_user_input` → **Codex**，立刻调用
2. 否则有 `AskUserQuestion` 或 `ask_user_question` → **Claude / Grok / Qwen Code**，立刻调用
3. 其它同构多选题工具 → 立刻调用
4. 仅不存在或调用失败 → 一句说明后 Markdown 降级

| YOU MUST | YOU MUST NOT |
|----------|--------------|
| 报告后同一轮 tool call | 问「是否进入问答？」 |
| 首个输出动作是 tool call | 先写 Markdown A/B/C 再等人打字 |
| 收到答案后再下一轮 / 交接 | 未收齐决策就交接给重生成 |
| 点选选项仅实质方案 | **手写** Other /「其他（请描述）」选项（客户端已提供） |

**题量闸门（强制）：**

| 规则 | 值 |
|------|-----|
| 默认只问 | 阻断 + 重要 |
| 建议级 | 默认不进问卷（可写报告跟进） |
| 硬上限 | **≤ 15 题**；用户要求深挖可 **≤ 25** |
| 超出 | 同维/同型合并；可行业默认的交接时标 ❓，**禁止静默丢弃**（写入报告「未澄清项」） |
| 单次题量 | Claude/Grok/Qwen 尽量打满 1–4；Codex 1–3（prefer 1 仅当题极重）；Markdown ≤8 |
| 轮次预告 | 报告或首轮 tool 前用一行说明预计题数/轮数（如「约 10 题 / 3 轮」） |

推荐项第一（Claude/Grok/Qwen 可选 ✅；Codex 用 ` (Recommended)`）。分组顺序：D1+D2 → D8+D9 → D6+D7 → D3+D4+D10 → D11–D17。

若当前为**只读 Plan** 且无法点选：提示用户进入可交互模式或开启对应 feature，再降级 Markdown。

**收齐回答后**，整理为 PM 回答记录（格式见 `references/qa-generation-guide.md` 文末），写入交接物，声明下一步调用 prd-regeneration。

## 交接协议（阶段 3 由配套 skill 执行）

本 skill 不重生成 PRD。完整模式收齐决策后，交接物为：

| 交接物 | 来源 | 用途 |
|--------|------|------|
| 原始 PRD | 用户提供 | 重生成时保留原始意图 |
| 审查报告 | 阶段 1 产出 | 问题清单与模型推导记录 |
| PM 回答记录 | 阶段 2 产出 | 产品决策，直接写入新 PRD |

报告末尾按模板写交接声明。轻量模式无交接（用户之后说「重生成 / 继续」再交）。**禁止在本 skill 内自行重生成 PRD 或验证图**——那是 `prd-regeneration` 的职责。

## 审查原则（精简）

- 引用原文；说明技术风险；给可执行改法。
- 你是开发，不是校对；假设 PM 已尽力——用「缺失」多于「错误」。
- 已有产物有则严格审；没提供不定级、不扣分、不催补图（文字/表格覆盖该图关注点即等价）。
