# DFD 数据流图审阅标准

维度 D13 审查时使用的基准，双重用途：PM 提供了 DFD（Data Flow Diagram，数据流图）→ 阶段 1 按本标准**严格**审查（A–D 全量）；未提供 → **不因缺图定级/扣分**——按下方「本图关注点」核对 PRD 文字/表格/规则表是否覆盖，阶段 3 生成 DFD（仅当数据流转跨多个模块或外部系统时）后按本标准自检。

## 本图关注点（无图时按此核对；形态无关）

DFD 要验证的核心是**数据链条完整、可追溯**。无图时核对 PRD 文字/表格/规则表是否说清：

- 核心数据从哪来（外部实体/系统）？
- 数据经过哪些加工（处理环节）？加工有功能描述吗？
- 数据存到哪（数据实体/存储）？
- 数据去向哪里（消费方/外部系统）？
- 链条与 PRD 功能模块、数据实体、涉及角色一致吗？

上述关注点被文字/表格覆盖即视为等价于有图，**不因缺图扣分**；图专业规范（B、C 节）仅在审查实际提供的 DFD 或 AI 生成 DFD 自检时使用。

本标准分 4 大块：A. DFD 完整性、B. DFD 规范正确性、C. 分层一致性、D. DFD 与 PRD 一致性。

---

## A. DFD 完整性

### 查什么

DFD 是否覆盖了本功能涉及的所有数据流？

### 合格

- 至少包含 Context 图或 Level 0 图
- DFD 中出现了 PRD 功能模块中涉及的所有外部实体（用户、第三方系统、管理员等）
- DFD 中出现了 PRD 数据实体表中定义的所有数据存储（数据库表、缓存、文件等）
- 每个加工（Process）都有明确的功能描述
- 数据流都有命名，且命名与数据字典一致

### 缺失（标记为重要/建议）

- DFD 中缺少 PRD 提到的外部实体 → 重要
- DFD 中缺少 PRD 数据实体表中定义的数据存储 → 重要
- 加工没有功能描述或编号 → 重要
- 数据流没有命名 → 重要
- 只有 Context 图没有 Level 0 展开 → 建议

---

## B. DFD 规范正确性

### 查什么

DFD 是否符合 Gane-Sarson 或 Yourdon/DeMarco 规范？是否存在常见的 DFD 错误？

### 合格

- 每个加工至少有一个输入数据流和一个输出数据流
- 数据存储必须通过加工来访问（外部实体不能直接读写数据存储）
- 两个数据存储之间不能直接流动数据（必须通过加工）
- 两个外部实体之间不能直接流动数据（必须通过加工）
- 数据流是数据（不是控制信号），不标注"激活"、"触发"、"开始"等控制流
- 数据流的命名是名词短语（如"用户信息"、"订单数据"），不是动词

### 缺失（标记为阻断/重要）

| 反模式 | DFD 中的例子 | 规范依据 | 严重程度 |
|--------|-------------|---------|---------|
| 黑洞（Black Hole） | 加工只有输入没有输出 | 加工必须有输出，否则数据消失 | 阻断 |
| 白洞/奇迹（Miracle） | 加工只有输出没有输入 | 加工必须有输入，否则数据凭空产生 | 阻断 |
| 灰洞（Grey Hole） | 加工输入是"用户ID"，输出是"完整订单信息" | 输入数据不足以产生输出 | 重要 |
| 外部实体直连存储 | 用户直接读写数据库，中间无加工 | 数据存储必须通过加工访问 | 阻断 |
| 存储间直连 | 数据库 A 直接流向数据库 B | 两个存储间必须通过加工 | 阻断 |
| 实体间直连 | 用户直接发送数据给支付平台 | 两个外部实体间必须通过加工 | 阻断 |
| 控制流当数据流 | 数据流标注"点击提交按钮" | DFD 只显示数据流，不显示控制流 | 重要 |
| 数据流命名不当 | 数据流叫"验证用户信息"（动词） | 数据流应命名为"用户信息"（名词） | 建议 |
| 加工名是数据流 | 加工叫"用户信息" | 加工名应是动作"验证用户信息" | 建议 |

---

## C. 分层一致性

### 查什么

如果 DFD 是多层的（Context → Level 0 → Level 1），父子图之间的数据流是否平衡？子图的输入输出是否与父图对应加工的输入输出一致？

### 合格

- Context 图中的每个数据流，在 Level 0 图中都能找到对应的入口/出口
- Level 0 中每个加工的输入输出，在其 Level 1 展开图中保持一致
- 父图中流入加工的数据流 = 子图中所有加工的外部输入之和
- 父图中流出加工的数据流 = 子图中所有加工的外部输出之和
- 数据存储在父子图中命名一致

### 缺失（标记为重要）

| 反模式 | DFD 中的例子 | 为什么是问题 | 严重程度 |
|--------|-------------|-------------|---------|
| 子图缺父图流 | Context 图有"订单数据"流，Level 0 没有这个流 | 父子图不平衡，数据流丢失 | 重要 |
| 子图多出父图流 | Level 0 某加工有"退款通知"输出，但父图加工没有这个输出 | 父子图不平衡，新增未声明的流 | 重要 |
| 存储命名不一致 | Context 图叫"订单库"，Level 0 叫"订单表" | 开发无法确认是否是同一个存储 | 建议 |
| 过度分解 | Level 1 图有 15+ 个加工 | 超过 7±2 原则，难以理解和维护 | 建议 |
| 分解不足 | 复杂加工没有展开为子图 | 加工描述过粗，开发无法细化实现 | 建议 |

---

## D. DFD 与 PRD 一致性

### 查什么

DFD 中的加工、数据流、数据存储是否与 PRD 的功能模块、数据实体、业务规则一致？

### 合格

- DFD 中的每个加工都能在 PRD 的功能模块中找到对应
- DFD 中的每个数据存储都能在 PRD 的数据实体表中找到对应
- DFD 中的每个外部实体都能在 PRD 的"涉及角色/系统"中找到对应
- DFD 数据流的粒度与 PRD 业务规则的粒度匹配（如 PRD 有"券校验规则"，DFD 应有对应的校验加工）
- 数据字典中的数据项与 PRD 数据实体表的字段一致

### 缺失（标记为阻断/重要）

| 反模式 | PRD 写的 | DFD 画的 | 严重程度 |
|--------|---------|---------|---------|
| 加工缺失 | PRD 有"券核销"功能模块 | DFD 中没有"核销"加工 | 阻断 |
| 存储缺失 | PRD 数据实体表有"优惠券表" | DFD 中没有对应的数据存储 | 阻断 |
| 实体缺失 | PRD 提到"支付平台"外部系统 | DFD 外部实体中没有"支付平台" | 重要 |
| 流与规则不匹配 | PRD 有"校验券有效期"规则 | DFD 中"领券"加工没有这个校验步骤 | 重要 |
| 数据项不一致 | PRD 中券实体有"使用门槛"字段 | 数据字典中没有"使用门槛" | 建议 |
| 权限未体现 | PRD 有"管理员可查看所有订单" | DFD 中没有体现权限控制的数据流 | 建议 |

---

## 审查结论判定

DFD 审查完成后，结合以下规则给 D13 维度打分：

| 分数 | 含义 | 标准 |
|------|------|------|
| **3** | 优秀 | DFD 完整、规范、分层平衡、与 PRD 完全一致，有数据字典。 |
| **2** | 合格 | 仅有建议级问题。基本完整规范，少量命名或粒度问题。 |
| **1** | 需改进 | 发现有重要问题。缺少部分实体/存储，或有规范错误（灰洞、命名问题）。 |
| **0** | 严重缺失 | 有阻断级问题。有黑洞/白洞/直连等严重规范错误。 |

> 未提供 DFD 时不按本表打分——阶段 1 按「本图关注点」核对文字/表格覆盖度打分（见 review-checklist D13 评分指南），本表仅作为阶段 3 生成 DFD 的自检标准。
