# UX 审阅标准

维度 D12 审查时使用的基准，双重用途：PM 提供了 UX 用户流程图/用户旅程图 → 阶段 1 按本标准**严格**审查（A–D 全量）；未提供 → **不因缺图定级/扣分**——按下方「本图关注点」核对 PRD 文字/表格/规则表是否覆盖，阶段 3 生成 UX 流程图（用户路径对体验关键时）后按本标准自检。

## 本图关注点（无图时按此核对；形态无关）

UX 流程图要验证的核心是**用户走完核心任务的路径完整、无断点**。无图时核对 PRD 文字/表格/规则表是否说清：

- 核心用户任务（如"领取优惠券 → 使用 → 下单"）的完整路径？
- 路径覆盖正常流程 + 主要异常分支（登录失败、权限不足、操作超时）？
- 每个步骤的下一步明确（用户做完一步之后去哪）？
- 页面层级与导航关系（信息架构）清晰？

上述关注点被文字/表格覆盖即视为等价于有图，**不因缺图扣分**；UX 体验细则（B、C、D 节）仅在审查实际提供的图或 AI 生成图自检时使用。

本标准分 4 大块：A. UX 流程图完整性、B. 用户路径效率、C. 交互一致性、D. 无障碍与错误体验。

---

## A. UX 流程图完整性

### 查什么

用户体验流程图（用户旅程图、任务流程图、或信息架构图）是否覆盖了主要用户场景？

### 合格

- 用户流程图展示了用户从进入系统到完成核心任务的路径
- 流程图覆盖了正常流程 + 主要异常分支（如登录失败、权限不足、操作超时）
- 每个步骤标注了：用户目标、页面/界面、系统响应、可能的错误
- 信息架构图展示了页面层级关系和导航结构
- 用户旅程图标注了用户情绪曲线（如有）

### 缺失（标记为重要）

- 只画了正常流程，没有异常分支 → 重要
- 流程图中缺少页面/界面标注 → 重要
- 信息架构缺失——开发不知道页面之间怎么跳转 → 重要
- 核心用户场景（如"领取优惠券 → 使用 → 下单"）没有对应的流程图 → 重要

## B. 用户路径效率

### 查什么

用户完成核心任务需要多少步？有没有不必要的步骤或冗余操作？是否存在可以合并或省略的步骤？

### 合格

- 核心任务（如"领取优惠券并下单"）的用户路径清晰，步骤数合理
- 没有"为了流程而流程"的冗余步骤
- 高频操作（如搜索、筛选）触手可及，不需要深层导航
- 返回/撤销操作在每个步骤都可用

### 缺失（标记为重要）

| 反模式 | UX 中的例子 | 为什么是问题 | 严重程度 |
|--------|-------------|-------------|---------|
| 路径过长 | 领取优惠券需要 7 步（进入首页→找入口→进列表→选券→确认→领成功→返回） | 用户流失率高，转化率低 | 重要 |
| 深层导航 | 常用功能埋在 3 层以上菜单里 | 用户找不到功能 | 重要 |
| 无返回路径 | 用户进入某页面后无法返回上一级 | 体验断裂，用户困在死胡同 | 重要 |
| 重复输入 | 用户在多个步骤重复填写相同信息 | 增加用户负担，降低完成率 | 重要 |
| 无撤销 | 删除/提交后没有撤销或二次确认 | 用户误操作无法挽回 | 重要 |
| 强制顺序 | 用户必须先完成 A 才能做 B，但 A 和 B 没有依赖关系 | 人为制造阻塞，降低效率 | 建议 |

---

## C. 交互一致性

### 查什么

同一类产品中的交互模式是否一致？是否遵循了 Ant Design 的设计规范？用户是否能在不同页面用相同的方式做相同的事？

### 合格

- 同类操作使用相同的交互模式（如所有"删除"都用 `Modal.confirm` 二次确认）
- 表单提交模式一致（有的页面自动保存，有的需要手动提交——如果有差异，是否有明确原因？）
- 列表/表格的交互模式一致（排序、筛选、分页方式统一）
- 错误提示的呈现方式一致（不用有的页面用弹窗，有的用 toast，有的 inline）
- 按钮位置、颜色语义一致（主操作蓝色、危险操作红色、次要操作默认）

### 缺失（标记为重要）

| 反模式 | UX 中的例子 | 为什么是问题 | 严重程度 |
|--------|-------------|-------------|---------|
| 同操作不同交互 | A 页面删除用弹窗确认，B 页面删除直接删 | 用户预期混乱，可能误操作 | 重要 |
| 按钮语义混乱 | "保存"按钮有时蓝色有时灰色 | 用户不知道哪个是主操作 | 重要 |
| 表单模式不一 | 有的表单实时保存，有的需要点提交 | 用户不知道当前表单的行为模式 | 重要 |
| 导航不一致 | 有的页面面包屑在顶部，有的在左侧 | 用户迷失方向 | 建议 |
| 错误提示不统一 | 有的错误用红色文字 inline，有的用弹窗 | 用户需要学习多种错误识别方式 | 建议 |

---

## D. 无障碍与错误体验

### 查什么

UX 是否考虑了不同能力用户的使用场景？错误发生时用户是否知道发生了什么、该怎么办？

### 合格

- 错误状态有明确的文案说明原因 + 可执行的操作建议（不只是"出错了"）
- 表单错误在字段旁边 inline 显示，用户不需要滚动找错
- 操作成功有明确反馈（不只是页面跳转）
- 加载状态有明确提示，用户知道系统在忙而不是卡死
- 空态有引导性文案 + 操作入口（"还没有订单，去逛逛" + 按钮）
- 关键操作有二次确认（删除、支付、批量操作）

### 缺失（标记为重要）

| 反模式 | UX 中的例子 | 为什么是问题 | 严重程度 |
|--------|-------------|-------------|---------|
| 错误文案模糊 | "系统异常"——用户不知道怎么办 | 用户卡住，可能直接离开 | 重要 |
| 无操作引导 | 空态只有"暂无数据"，没有下一步操作 | 用户不知道接下来该做什么 | 重要 |
| 错误位置远 | 表单提交失败，错误提示在页面顶部 | 用户需要滚动才能看到错误 | 重要 |
| 无加载反馈 | 点击后页面无变化，用户以为没点到 | 用户会重复点击，导致重复提交 | 重要 |
| 危险操作无确认 | 删除直接删除，没有二次确认 | 用户误删后无法恢复 | 重要 |
| 成功无反馈 | 提交后页面跳转，用户不知道是否成功 | 用户不确定操作结果 | 建议 |

---

## 审查结论判定

UX 审阅完成后，结合以下规则给 D12 维度打分：

| 分数 | 含义 | 标准 |
|------|------|------|
| **3** | 优秀 | 流程图完整覆盖所有场景，用户路径最优，交互高度一致，错误体验完善。 |
| **2** | 合格 | 仅有建议级问题。流程基本完整，少量不一致或冗余步骤。 |
| **1** | 需改进 | 发现有重要问题。流程覆盖不完整、路径过长、或交互不一致多处。 |
| **0** | 严重缺失 | 核心流程存在严重可用性缺陷（如用户无法完成核心任务）。 |

> 未提供 UX 流程图时不按本表打分——阶段 1 按「本图关注点」核对文字/表格覆盖度打分（见 review-checklist D12 评分指南），本表仅作为阶段 3 生成 UX 流程图的自检标准。
