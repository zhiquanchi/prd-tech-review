# 流程图审阅标准

维度 D15 审查时使用的基准。审查 PRD 中是否包含业务流程图（Flowchart），以及流程图是否逻辑完整、分支覆盖、与 PRD 描述一致。

流程图展示的是**业务逻辑的处理顺序和决策分支**——"先做什么、然后做什么、如果满足条件走 A 路径、否则走 B 路径"。它不同于 DFD（数据怎么流）、状态机（状态怎么变）、UX 流程图（用户怎么走），流程图聚焦于**系统内部的处理逻辑和分支决策**。

本标准分 4 大块：A. 流程图完整性、B. 逻辑正确性、C. 决策分支完备性、D. 流程图与 PRD 一致性。

---

## A. 流程图完整性

### 查什么

PRD 是否为每个核心业务流程提供了流程图？流程图是否有明确的开始和结束？

### 合格

- PRD 为每个核心业务流程（如"领券→用券→下单"、"退款审批"、"券核销"）提供了流程图
- 每个流程图有明确的开始节点（起点）
- 每个流程图有明确的结束节点（终点），且终点数量合理
- 流程图覆盖了主流程 + 异常分支（不只是"快乐路径"）
- 流程图中的每个步骤都有清晰的命名，命名是动作短语（如"校验券有效期"），不是名词

### 缺失（标记为阻断/重要）

- PRD 的核心业务流程没有对应的流程图 → 阻断
- 流程图没有开始节点 → 重要
- 流程图没有结束节点（流程无限延伸） → 重要
- 只画了正常流程，没有异常分支 → 重要
- 步骤命名是名词而非动作（如"优惠券"而不是"校验优惠券"） → 建议
- 核心业务流程只在文字中描述，没有可视化流程图 → 阻断

---

## B. 逻辑正确性

### 查什么

流程图的处理逻辑是否正确？是否存在死循环、不可达路径、或逻辑矛盾？

### 合格

- 流程图中不存在死循环（无限循环没有退出条件）
- 流程图中不存在不可达路径（某条分支永远走不到）
- 每个处理步骤的输入来源明确（上一步的输出 = 这一步的输入）
- 没有逻辑矛盾（如"校验通过"后紧接着又判断"校验失败"的分支）
- 并行处理步骤有汇合点（分叉后最终合流）

### 缺失（标记为阻断/重要）

| 反模式 | 流程图中的例子 | 为什么是问题 | 严重程度 |
|--------|-------------|-------------|---------|
| 死循环 | "重试"步骤循环回自身，没有最大重试次数 | 系统无限重试，资源耗尽 | 阻断 |
| 不可达路径 | "校验失败→跳转错误页"分支前有一个永真的守卫条件 | 分支永远走不到，代码白写 | 重要 |
| 逻辑矛盾 | "校验通过"后紧接着判断"如果校验失败" | 校验已通过，不可能再失败 | 重要 |
| 分叉不汇合 | 并行处理分叉后没有汇合点 | 开发不知道两条分支的结果如何合并 | 重要 |
| 输入输出断裂 | 步骤 A 输出"订单ID"，步骤 B 输入"券ID" | 上下游数据不匹配，流程断裂 | 重要 |
| 缺少异常出口 | 某步骤可能失败但没有失败分支 | 失败时系统不知道怎么办 | 重要 |
| 步骤过于粗略 | "处理订单"一个框包含 10 个子操作 | 开发不知道里面具体做什么 | 建议 |
| 步骤过于细碎 | 一个简单操作拆成 8 个流程框 | 流程图过于复杂，难以阅读 | 建议 |

---

## C. 决策分支完备性

### 查什么

每个决策菱形（判断框）是否覆盖了所有可能的结果？是否有遗漏的分支？

### 合格

- 每个决策点都列出了所有可能的分支（如"是/否"、"成功/失败/部分成功"）
- 二元决策（是/否）确实只有两种可能，没有第三种遗漏
- 多元决策（如"按用户类型分支：VIP/普通/游客"）穷举了所有类型
- 每个分支都导向明确的下一步（没有"悬空"分支——不知道去哪）
- 默认/兜底分支有明确说明（如"其他情况 → 走默认流程"）

### 缺失（标记为阻断/重要）

| 反模式 | 流程图中的例子 | 缺了什么 | 严重程度 |
|--------|-------------|---------|---------|
| 分支遗漏 | 决策"支付方式"只有"微信/支付宝"分支，缺"银联/余额" | 没有穷举所有支付方式 | 重要 |
| 二元决策有第三种可能 | "校验通过？"只画了是/否，但实际还有"校验超时" | 遗漏超时分支 | 重要 |
| 悬空分支 | "校验失败→"箭头指向空白 | 失败后不知道怎么办 | 阻断 |
| 无默认分支 | 多元决策"用户类型：VIP/普通"但没有"其他"分支 | 如果来了一个未知类型呢？ | 重要 |
| 分支结果重叠 | "金额>100→走A"和"金额≥100→走B" | 100 元时走 A 还是 B？ | 重要 |
| 决策条件模糊 | 判断框写"是否满足条件"——什么条件？ | 开发不知道判断什么 | 重要 |
| 缺少超时分支 | "等待支付回调"只有"成功/失败"没有"超时" | 支付一直不回调怎么办？ | 重要 |
| 缺少并发分支 | "用户同时提交两次"没有并发处理分支 | 重复提交产生重复订单 | 重要 |

---

## D. 流程图与 PRD 一致性

### 查什么

流程图中的处理步骤、决策条件、分支结果是否与 PRD 的功能模块、业务规则、操作规则表一致？

### 合格

- 流程图中的每个处理步骤都能在 PRD 的功能模块或业务规则中找到对应
- 流程图中决策条件与 PRD 业务规则的判断条件一致（如 PRD 规则"满 100 元可用券"，流程图判断"订单金额 ≥ 100"）
- 流程图中的异常分支与 PRD 异常处理表的场景对应
- 流程图的开始/结束与 PRD 描述的流程入口/出口一致
- 流程图中涉及的状态变化与状态机图（D14）一致
- 流程图中涉及的数据操作与 DFD 数据流图（D13）一致

### 缺失（标记为阻断/重要）

| 反模式 | PRD 写的 | 流程图画 | 严重程度 |
|--------|---------|---------|---------|
| 步骤无对应 | PRD 有"券校验"规则但流程图没有校验步骤 | 缺少校验环节 | 阻断 |
| 条件不一致 | PRD 规则"满 100 元" | 流程图判断">100"（缺了等于） | 重要 |
| 异常分支不匹配 | PRD 异常表有"断网重试" | 流程图没有断网分支 | 重要 |
| 流程入口不一致 | PRD 写"用户从首页进入" | 流程图入口是"用户从消息推送进入" | 重要 |
| 状态变化不一致 | 状态机图（D14）有"已冻结"状态 | 流程图没有冻结相关步骤 | 重要 |
| 数据操作不一致 | DFD（D13）有"写入退款记录" | 流程图退款流程没有写记录步骤 | 重要 |
| 结果不一致 | PRD 写"领券成功后跳转券列表" | 流程图领券成功后跳转首页 | 重要 |
| 缺少前置条件 | PRD 写"需要登录才能领券" | 流程图没有登录检查步骤 | 重要 |

## 流程图与其他图表的关系

流程图不是孤立存在的，它需要与 PRD 中的其他图表相互印证：

| 图表类型 | 聚焦视角 | 与流程图的关系 |
|---------|---------|--------------|
| **流程图（本维度）** | 系统处理逻辑和决策分支 | — |
| DFD 数据流图（D13） | 数据怎么流 | 流程图中的处理步骤应对应 DFD 中的加工；流程图中的数据读写应对应 DFD 中的数据流 |
| 状态机图（D14） | 状态怎么变 | 流程图中涉及状态变化的步骤应与状态机图的转换一致 |
| UX 流程图（D12） | 用户怎么走 | UX 流程图是用户视角的路径；流程图是系统视角的处理逻辑——两者描述同一流程但视角不同 |
| UI 原型（D11） | 界面长什么样 | 流程图中的用户交互步骤应对应原型中的可点击操作 |

---

## 审查结论判定

流程图审查完成后，结合以下规则给 D15 维度打分：

| 分数 | 含义 | 标准 |
|------|------|------|
| **3** | 优秀 | 核心流程都有流程图，逻辑正确，分支完备，与 PRD 及其他图表完全一致。 |
| **2** | 合格 | 仅有建议级问题。流程图基本完整，少量步骤命名或粒度问题。 |
| **1** | 需改进 | 发现有重要问题。缺少部分异常分支、决策条件模糊、或与 PRD 有不一致。 |
| **0** | 严重缺失 | 有阻断级问题。核心流程没有流程图、有死循环/悬空分支/逻辑矛盾等严重错误。 |
