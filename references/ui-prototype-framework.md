# UI 原型 / 设计稿审查标准（D11）

维度 D11 审查时使用的基准。**仅当 PM 提供了原型或设计稿时执行**；未提供则跳过、不定级。原型**不在**阶段 3 自动生成范围内，仍需人工产出。

## 形态分级（先定形态，再选检查深度）

| 形态 | 执行哪些块 | 定级原则 |
|------|------------|----------|
| 可交互 Ant Design（v5/v6）等组件库代码 | A + B + C + D | 完整规范；组件 API 适用 |
| 可交互其它技术栈（小程序/Flutter/其它 Web） | A + C + D | B（antd 专条）标「不适用」 |
| 高保真设计稿（Figma 等） | A（覆盖）+ D | 无法验证真实交互；**不因「非代码」阻断**；问题通常最高为**重要** |
| 纯静态截图 | A（覆盖）+ D | 覆盖不全/与 PRD 矛盾 → **重要** |
| 未提供 | 整维跳过 | 不定级 |

本标准分 4 大块：A. 完整性与覆盖、B. Ant Design 组件规范（仅 antd 代码）、C. 状态与交互（可交互代码）、D. 与 PRD 一致性（所有形态）。

---

## A. 完整性与覆盖

### 查什么

PRD 中提到的页面/视图，产物里是否都有对应？可交互原型能否走通主流程？

### 合格

- PRD 中每个功能模块在产物中都有对应页面/帧
- **代码原型**：可点击、切换、提交，主流程可走通；页面跳转关系清晰
- **设计稿/截图**：关键页面与状态（空/错/满）有视觉覆盖，并与 PRD 文案大致一致

### 缺失（按形态定级）

| 情况 | 可交互代码 | 设计稿 / 截图 |
|------|------------|---------------|
| PRD N 页只覆盖部分 | 关键页缺失 → **阻断** | **重要** |
| 不可交互 / 无事件绑定 | **阻断** | 不适用（设计稿本来不可点）→ 记「交互未验证」**重要** |
| 仅因不是 Ant Design | **不定级**（换栈用其它规范） | **不定级** |

## B. Ant Design 组件使用规范

### B1. 是否重复造轮子

#### 查什么

原型中有没有手写已有 Ant Design 组件能直接实现的功能？

#### 合格

- 表格用 `<Table>`，表单用 `<Form>` + `<Form.Item>`
- 日期选择用 `<DatePicker>`，下拉选择用 `<Select>`
- 弹窗用 `<Modal>`，抽屉用 `<Drawer>`
- 提示用 `<message>` / `<notification>` / `<Modal.confirm>`

#### 缺失（标记为重要）

| 反模式 | 原型中的例子 | 应该用哪个组件 | 严重程度 |
|--------|-------------|--------------|---------|
| 手写表格 | 用 `<div>` + `map` 拼表格 | `<Table dataSource columns>` | 重要 |
| 手写弹窗 | 用 `<div>` + `display:none` 模拟弹窗 | `<Modal open onOk>` | 重要 |
| 手写下拉 | 用 `<input>` + 自写下拉列表 | `<Select options>` | 重要 |
| 手写日期 | 用 `<input type="date">` | `<DatePicker>` | 建议 |
| 手写 Tab | 用 `<button>` + state 切换 | `<Tabs items>` | 重要 |
| 手写分页 | 用 `<button>` + 手动计算 | `<Table pagination>` 或 `<Pagination>` | 重要 |

### B2. 组件 API 是否正确使用

#### 查什么

Ant Design 组件的 props 是否正确传递？有没有用了已废弃的 API？

#### 合格

- `<Table>` 用 `dataSource` + `columns`（不是 `data` + `columns`）
- `<Form>` 用 `onFinish`（不是 `onSubmit`）
- `<Modal>` 用 `open`（v5+，不是 v4 的 `visible`）
- `<Select>` 用 `options` prop 或 `<Select.Option>` 子组件（二选一，不混用）
- `<Form.Item>` 的 `name` 与数据字段对应

#### 缺失（标记为重要）

| 反模式 | 原型中的例子 | 正确写法 | 严重程度 |
|--------|-------------|---------|---------|
| API 拼写错误 | `<Table data={list}>` | `<Table dataSource={list}>` | 重要 |
| 用废弃 API | `<Modal visible={true}>` | `<Modal open={true}>` | 建议 |
| name 不匹配 | `<Form.Item name="userName">` 但数据字段是 `username` | `<Form.Item name="username">` | 重要 |
| 混用 API 风格 | `<Select options={[...]}><Select.Option>...</Select.Option></Select>` | 只用 `options` 或只用 `<Select.Option>` | 建议 |
| 缺少 key | 列表渲染没有 `key` prop | 每个 `<Table.Column>` 或列表项加 `key` | 建议 |

### B3. 布局是否使用 Ant Design 栅格

#### 查什么

页面布局是否使用 `<Row>` / `<Col>` 栅格系统？还是用自定义 CSS flex/grid？

#### 合格

- 页面整体布局用 `<Layout>` + `<Header>` + `<Content>` + `<Sider>`
- 栅格用 `<Row gutter={16}>` + `<Col span={8}>`
- 表单布局用 `<Form layout="horizontal|vertical|inline">`

#### 缺失（标记为建议）

- 用自定义 CSS 代替 `<Row>` / `<Col>` → 建议（不阻断但偏离规范）
- 没有用 `<Layout>` 而是手写 header → 建议

### B4. 图标是否使用 @ant-design/icons

#### 查什么

图标是否从 `@ant-design/icons` 引入？还是用了第三方图标库或内联 SVG？

#### 合格

```tsx
import { SearchOutlined, PlusOutlined, DeleteOutlined } from '@ant-design/icons';
<Button icon={<SearchOutlined />}>搜索</Button>
```

#### 缺失（标记为建议）

- 用了 emoji 当图标 → 建议
- 用了第三方图标库（如 react-icons）→ 建议
- 内联了大段 SVG → 建议

## C. 状态与交互覆盖

### C1. 空态是否实现

#### 查什么

列表/表格无数据时，原型是否使用了 `<Empty>` 组件？

#### 合格

```tsx
<Table dataSource={[]} locale={{ emptyText: <Empty description="还没有优惠券" /> }} />
```

#### 缺失（标记为重要）

- 数据为空时页面空白，没有 `<Empty>` 组件
- 空态没有操作引导（如"去领券"按钮）

### C2. 加载态是否实现

#### 查什么

数据加载时是否使用了 `<Skeleton>` / `<Spin>` / Table 的 `loading` prop？

#### 合格

```tsx
<Table loading={true} />
<Spin tip="加载中..." />
<Skeleton active paragraph={{ rows: 5 }} />
```

#### 缺失（标记为重要）

- 没有加载态——点击后页面无任何反馈
- 用 `alert("加载中")` 代替 `<Spin>`

### C3. 表单校验是否实现

#### 查什么

表单字段是否有校验规则？校验失败是否有错误提示？

#### 合格

```tsx
<Form.Item
  name="phone"
  label="手机号"
  rules={[
    { required: true, message: '请输入手机号' },
    { pattern: /^1\d{10}$/, message: '请输入正确的手机号' }
  ]}
>
  <Input maxLength={11} />
</Form.Item>
```

#### 缺失（标记为重要）

| 反模式 | 原型中的例子 | 缺了什么 | 严重程度 |
|--------|-------------|---------|---------|
| 无校验规则 | `<Form.Item name="phone"><Input /></Form.Item>` | 没有 `rules` | 重要 |
| 无必填标记 | 必填字段没有 `required: true` | 用户不知道哪些必须填 | 重要 |
| 无错误提示 | 校验失败没有 `message` | 用户不知道哪里错了 | 重要 |
| 用 alert 提示 | `onFinish` 里 `alert("请填写手机号")` | 应该用 Form 的字段级校验 | 建议 |

### C4. 反馈机制是否完整

#### 查什么

操作成功/失败后是否有 Ant Design 的反馈组件？

#### 合格

```tsx
message.success('提交成功');
message.error('网络错误，请重试');
Modal.confirm({ title: '确认删除？', onOk: handleDelete });
notification.success({ message: '保存成功' });
```

#### 缺失（标记为重要）

- 提交成功后无任何反馈（页面没变化）
- 用 `alert("成功")` 代替 `message.success`
- 删除操作没有二次确认（缺 `Modal.confirm`）

### C5. 分页是否实现

#### 查什么

数据列表是否配置了分页？

#### 合格

```tsx
<Table dataSource={data} pagination={{ pageSize: 10, showSizeChanger: true }} />
```

#### 缺失（标记为重要）

- 列表一次性加载所有数据，无分页配置
- PRD 说"每页 10 条"但原型 `pagination` 没配 `pageSize`

## D. PRD 与原型一致性

### D1. 页面结构一致性

#### 查什么

PRD 的"页面布局"章节描述的区域，与原型的实际布局是否对应？

#### 合格

- PRD 写了 3 个区域（Tab 栏、券列表、底部按钮），原型正好这 3 个区域
- PRD 写"Tab 栏在顶部"，原型 Tab 栏确实在顶部
- PRD 写"券卡片显示金额、名称、有效期"，原型卡片正好显示这 3 个字段

#### 缺失（标记为阻断）

| 反模式 | PRD 写的 | 原型实现的 | 严重程度 |
|--------|---------|-----------|---------|
| 区域缺失 | PRD 写了"筛选区" | 原型里没有筛选区 | 阻断 |
| 位置不一致 | PRD 写"Tab 栏在顶部" | 原型 Tab 栏在左侧 | 重要 |
| 字段不一致 | PRD 写"显示有效期" | 原型没显示有效期 | 阻断 |
| 多出来的东西 | PRD 没提"批量操作" | 原型有批量操作栏 | 重要 |

### D2. 操作规则一致性

#### 查什么

PRD 的"操作规则表"中每个按钮的行为，与原型绑定的事件是否一致？

#### 合格

- PRD 写"点击立即使用 → 跳转商品列表页"，原型 `<Button onClick={goToProducts}>` 确实跳转
- PRD 写"券过期时按钮置灰"，原型确实有 `disabled={isExpired}` 逻辑
- PRD 写"切换 Tab 刷新列表"，原型 `onChange` 确实触发刷新

#### 缺失（标记为阻断）

| 反模式 | PRD 写的 | 原型实现的 | 严重程度 |
|--------|---------|-----------|---------|
| 事件未绑定 | PRD 写"点击跳转" | 按钮 `onClick` 是空的 | 阻断 |
| 行为不一致 | PRD 写"过期置灰" | 原型过期券按钮可点击 | 重要 |
| 缺条件判断 | PRD 写"未登录跳登录页" | 原型没有登录态判断 | 重要 |
| 交互方式不同 | PRD 写"点击展开" | 原型是 hover 展开 | 重要 |

### D3. 数据展示一致性

#### 查什么

PRD 的"数据展示表"中描述的排序、数量、格式，与原型是否一致？

#### 合格

- PRD 写"按领取时间倒序"，原型 `dataSource` 确实按时间倒序
- PRD 写"每页 10 张"，原型 `pagination.pageSize = 10`
- PRD 写"金额显示 ¥10"，原型确实格式化为 `¥{value}`
- PRD 写"过期券灰显"，原型确实加了灰色样式

#### 缺失（标记为重要）

| 反模式 | PRD 写的 | 原型实现的 | 严重程度 |
|--------|---------|-----------|---------|
| 排序不一致 | "按时间倒序" | 原型按正序或无排序 | 重要 |
| 数量不一致 | "每页 10 条" | 原型 `pageSize = 20` | 重要 |
| 格式不一致 | "显示 ¥10.00" | 原型显示 `10` | 建议 |
| 特殊样式缺失 | "过期券灰显" | 原型所有券样式相同 | 重要 |

### D4. 异常处理一致性

#### 查什么

PRD 的"异常处理表"中每个场景，原型是否有对应的实现？

#### 合格

- PRD 写"断网时显示重试按钮"，原型有网络错误状态 + 重试按钮
- PRD 写"空态显示插画 + 文案"，原型用了 `<Empty>` + 自定义文案
- PRD 写"加载中显示骨架屏"，原型用了 `<Skeleton>`

#### 缺失（标记为重要）

| 反模式 | PRD 写的 | 原型实现的 | 严重程度 |
|--------|---------|-----------|---------|
| 空态未实现 | "空态显示插画" | 原型空数据时页面空白 | 重要 |
| 加载态未实现 | "加载中显示转圈" | 原型无 loading 状态 | 重要 |
| 断网未实现 | "断网显示重试" | 原型无错误处理 | 重要 |
| 反馈方式不一致 | "用 Modal 确认删除" | 原型用 `window.confirm` | 建议 |

## 审查结论判定

仅当执行了 D11 时打分；未提供产物则跳过、不打分。

| 分数 | 含义 | 标准 |
|------|------|------|
| **3** | 优秀 | 覆盖完整，与 PRD 一致；代码原型组件与状态规范。 |
| **2** | 合格 | 仅有建议级问题。 |
| **1** | 需改进 | 有重要问题（多处不一致、状态缺失、设计稿关键页不全等）。 |
| **0** | 严重缺失 | 有阻断级问题（可交互代码大量缺页、不可走通、或与 PRD 严重矛盾）。 |

> 设计稿/截图形态下，一般用 1–3 分表达缺口，**避免**仅因「不是 antd 代码」打 0 分。
